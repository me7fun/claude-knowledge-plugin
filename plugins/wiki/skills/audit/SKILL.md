# Wiki Audit — 重复盘点

> 所有回复使用用户的对话语言。本 skill 只**报告与提案**，合并／删除遵循写入政策（预设：须用户同意）。

为什么要有：提案前查重是**事前预防**，漏了没有人会知道——用户不可能记得每一页写过什么。
本 skill 是**事后抓漏**，不靠任何人的记忆。上次盘点清干净之后，这次再找到的重复，
就是这段期间事前查重漏掉的数量。

## 步骤 1：取地图与上次记录

1. 列出每页的小节标题（即时算出，带行号与行数）：
   `node "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-search.js" --outline`
   记下输出最后一行的总页数、总小节数。
2. 读 state 目录（`wiki.config.json` 的 `stateDir`，预设 `.claude/state/`）下的
   `wiki-audit-log.txt`——有的话，最后一行就是上次盘点的日期与结果；没有就是第一次盘点。

## 步骤 2：通读内容（不能只比标题）

重复的知识常常标题不同、内容相同，所以**要读内文**，地图只用来定位与分批：

- 页数少（约 30 页内）→ 全部读完。
- 页数多 → 按主题分批（照 `index-<slug>.md`），每批先为每个小节写一句话摘要，再拿摘要
  跨批比对；可疑的组合回头读原文确认。可用 subagent 并行分批，但最后的比对与结论自己做。
- 跨主题的重复最容易漏：对每个可疑主题词再跑一次
  `wiki-search.js <关键字...>` 看它还出现在哪些页的哪些小节。

没读完的范围要在报告里明说，不可以写「未发现重复」带过。

## 步骤 3：分类

| 类别 | 判准 |
|---|---|
| **矛盾** | 同一件事，两处说法不一致。最危险（读到哪一处就信哪一处），排最前面 |
| **重复** | 同一条知识完整写在两处 |
| **重叠** | 部分相同，但各有对方没有的内容 |

不算重复：一处是正本、另一处只有一句指标＋连结；同一主题但讲不同面向（例如一页讲「为什么」、
另一页讲「怎么操作」）。拿不准 → 列出来并标把握度「中」，让用户判断，不要自己吞掉。

## 步骤 4：输出报告

```text
Wiki 重复盘点（YYYY-MM-DD）

范围：N 页、M 个小节 —— [全部读完／只读了哪些主题、哪些没读]
上次盘点：[日期与结果，或「无记录（第一次）」]

发现 K 组：

1. [矛盾/重复/重叠] [一句白话：这两处在讲同一件什么事、差在哪]
   - A: <页>.md〈小节〉（第 N 行）
   - B: <页>.md〈小节〉（第 N 行）
   - 较晚加入: [A 或 B＋日期；知识库不在 git 里或查不到就写「未知」]
   - 建议: [以哪处为正本、另一处的哪些独有内容并过去、另一处删除或改成一句指标]
   - 把握度: 高／中（中＝需要你看一眼原文）

（或）未发现重复：[读了什么范围]

小结：矛盾 x／重复 y／重叠 z。
要照建议合并吗？（可以只选其中几条）
```

- 白话行与 /wiki:review 同一标准：用户不翻原文也能判断。
- 「较晚加入」用 `git blame -L <行>,<行> --date=short <页>` 查该小节标题行；它能回答
  「这条重复是在提案前查重上线之前还是之后产生的」。
- **矛盾项不要自己裁决哪边对**——列出两种说法，请用户决定，或提议用实测／读代码验证。

## 步骤 5：合并（用户同意后才动）

1. 一条知识只留一份正本：选内容较完整、所在页较合适的一处；把另一处**独有**的内容并进去，
   不丢信息。`sources`／`verified` 等 frontmatter 一并合并。
2. 另一处：整节删除，或留一句指标＋连结指向正本（读者会从那一页找过来时才留）。
3. 整页被并空 → 走 reference.md「六、索引维护」情境 3（删页、同步两层索引）。
4. 跑 `node "${CLAUDE_PLUGIN_ROOT}/scripts/wiki-lint.js"` 确认没有断链与索引不一致。
5. 未获裁决的矛盾项原样保留，在回复里列为待办。

## 步骤 6：留下记录（下次比较用）

在 state 目录的 `wiki-audit-log.txt` 追加一行（档案不存在就建；`.txt` 不会被开场注入当成进行中任务）：

```text
YYYY-MM-DD | N 页 M 小节 | 矛盾 x 重复 y 重叠 z | 已合并 k，未处理 j | plugin v<版本>
```

最后用一句话告诉用户：这次清到什么程度、下次盘点若再出现重复代表什么。
